# 37 · 多数据库支持与首启安装引导

> **这一篇解决什么问题**
> 平台原本只能用 SQLite —— 单机好用，但换台电脑就是另一份数据。
> 现在支持 SQLite / PostgreSQL / MySQL 三种，并且**首次打开网页会进入引导页**，
> 选完数据库当场做 5 项连接自检，全绿才允许继续。
>
> 设计底线有两条：
> 1. **自检没通过，绝不把连接串写进 `.env`** —— 否则用户会卡在一个连不上的系统里，连改都改不回来。
> 2. **任何情况下自检都不能抛异常** —— 这是用户看到的第一屏，抛栈等于劝退。

---

## 1. 三种方言的取舍

| 方言 | 异步驱动 | 适用场景 | 数据一致性 |
|---|---|---|---|
| **SQLite** | `aiosqlite`（随 requirements 装好） | 单机、便携版、快速试用 | 单文件，只能本机读写 |
| **PostgreSQL** | `asyncpg` | 多设备共享、生产环境；可叠加 TimescaleDB 做时序压缩 | ✅ 多设备指向同一库即一致 |
| **MySQL** | `aiomysql` | 团队已有 MySQL 运维体系 | ✅ 同上 |

用户的需求是「多台设备数据保持一致」，所以推荐路径是：
**在一台所有设备都能访问的内网机器上装 PostgreSQL（或复用现有 MySQL），各设备首启都指向同一个库。**

## 2. 首启流程

```
浏览器打开 http://host:8000
        │
        ▼
GET /api/v1/system/setup/status ─── needs_setup=true ?
        │ 是                                     │ 否
        ▼                                        ▼
  锁定到 #/setup 引导页                      正常进入系统
        │
        ├─ 步骤1：选数据库类型（卡片上直接标出「驱动已装/需 pip install」）
        ├─ 步骤2：填连接参数（或高级模式直接粘完整连接串）
        ├─ 步骤3：POST /system/setup/test  ── 5 项自检
        │          任意一项红 → 给出可照做的排查建议 → 「保存并完成」保持禁用
        └─ 步骤4：POST /system/setup/complete ── 写 .env → reset_engine → 跑启动任务
```

### 安装闸门

未完成安装时，`/api/v1/**` 下除 `/system/setup/*` 外**一律返回 503**：

```json
{
  "error": {
    "code": "setup_required",
    "message": "尚未完成安装引导：请先选择数据库并通过连接自检。",
    "detail": { "setup_endpoint": "/api/v1/system/setup/status" }
  }
}
```

这么做的原因：如果直接放行，用户会在一个没有库的系统里点来点去，
每个页面报一堆与「数据库没配」无关的错，真正的原因被埋掉。

### 老部署自动接管

`.env` 里没有 `SETUP_COMPLETED` 的老部署（升级上来的）不应该被逼着重装：

```python
ensure_adopted_existing_install(settings, min_tables=5)
# 库里已有 ≥5 张本平台表 → 自动置 SETUP_COMPLETED=true 并写回 .env
```

## 3. 连接自检的 5 项

`app/core/setup.py::probe_database()`，每一步都记耗时，任何一步炸都会被兜住并转成结构化报告：

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 连接串格式 | `detect_dialect()` 认不认得出方言；认不出直接给药方 |
| 2 | 异步驱动 | `is_driver_installed()`；缺驱动直接给 `pip install asyncpg -i <国内源>` |
| 3 | 建立连接 | 真正连上去，并取回服务端版本（`SELECT version()` / `@@version` / `sqlite_version()`） |
| 4 | 已有表对比 | 列出库里已存在的本平台表，提示「将复用现有库 / 将新建 45 张表」 |
| 5 | 读写权限 | 建一张 `_btc_setup_probe` 再删掉，确认有 DDL 权限 |

**报错必须翻译成人话**，见 `friendly_db_error()`：

| 原始错误 | 给出的建议 |
|---|---|
| 超时 | ① 主机是否可达 ② 端口是否放行 ③ 是否要走代理 |
| `getaddrinfo` 失败 | 主机名解析不了，换成 IP 再试 |
| `InvalidPassword` / `1045` | 用户名或口令不对 |
| `InvalidCatalogName` / `1049` | 数据库不存在，先 `CREATE DATABASE` |
| `InsufficientPrivilege` / `1044` | 账号没权限，需要授权 |
| `ConnectionRefused` / `2003` | 端口没监听 / 服务没起 |
| SSL 相关 | 先用 `sslmode=disable` 排除 SSL 配置问题 |
| SQLite `unable to open` | 目录不存在或无写权限，换目录 |

口令里有 `@ : / #` 时必须 URL 编码，否则会被当成主机分隔符 ——
`dialects.build_url()` 里统一 `quote(..., safe="")`，并且**自检接口不回显原始连接串**。

## 4. 跨方言差异收在哪里

新增一种方言只需要改两个文件：

### `backend/app/db/dialects.py`

```python
ASYNC_SCHEME   = {"sqlite": "sqlite+aiosqlite", "postgresql": "postgresql+asyncpg", "mysql": "mysql+aiomysql"}
DRIVER_PACKAGE = {"sqlite": "aiosqlite", "postgresql": "asyncpg", "mysql": "aiomysql"}

detect_dialect(url)      # 识别方言，认不出抛中文 ValueError
normalize_to_async(url)  # 把同步驱动（psycopg2/pymysql/psycopg）纠正为异步
is_driver_installed(d)   # find_spec 检查，不真正 import
install_hint(d)          # pip 安装命令（带国内源）
build_url(...)           # 按格子拼连接串，userinfo 一律 URL 编码
mask_url(url)            # 日志/回显用：user:***@host:port/path
describe(d) / supported_dialects()   # 给前端卡片的数据
```

### `backend/app/db/upsert.py`

| 方言 | Upsert 写法 | `DO NOTHING` 退化 |
|---|---|---|
| SQLite / PostgreSQL | `ON CONFLICT (…) DO UPDATE SET col = excluded.col` | `ON CONFLICT … DO NOTHING` |
| MySQL | `ON DUPLICATE KEY UPDATE col = VALUES(col)` | `INSERT IGNORE` |

MySQL 没有 `excluded`、也没有 `DO NOTHING`，这两点是唯一的语法分叉点，
`build_upsert()` 一次性吃掉了差异，业务代码（`db/repo.py`）里看不到任何 `if dialect ==`。

### DDL 兼容性

45 张表在三种方言下都用 `CreateTable(...).compile(dialect=…)` 编译过（离线、不需要真连库）。
踩到的 MySQL 约束：

- TEXT / JSON 列**不能有 DEFAULT**
- VARCHAR **必须给长度**（否则不能建索引）
- `port` 这类保留字需要反引号（SQLAlchemy 自动处理）

连接池参数也按方言分：`asyncpg` 用 `timeout`（float 秒），
`aiomysql`/`pymysql` 用 `connect_timeout`（int 秒），MySQL 额外加 `pool_recycle=28000` 防服务端断连。

## 5. 命令行

```bash
# 自检连接（和网页引导用的是同一套 probe_database）
python scripts/btcctl.py db-test --url "postgresql+asyncpg://btc:口令@10.0.0.5:5432/btc"
python scripts/btcctl.py db-test                     # 不带 --url 则测当前 DATABASE_URL

# 重置为未安装状态，下次打开网页重进引导页（只改标记，不动数据）
python scripts/btcctl.py setup-reset
```

`db-test` 退出码：0 全绿 / 1 有红项 / 2 没给连接串。

## 6. 代理测试：必须是服务端发起

顺带修掉的一个 bug：原来「系统设置 → 测试网络连接性」实际是**浏览器**在发请求，
于是「浏览器挂了代理就能通、服务器没挂就不通」这种错位根本测不出来。

现在 `POST /api/v1/system/proxy/test` 在服务端进程内发起，响应里回显发起方身份：

```json
{
  "initiator": {
    "role": "server",
    "role_cn": "服务端进程",
    "hostname": "btc-server",
    "python": "3.13.12",
    "pid": 12345,
    "local_ip": "10.0.0.5",
    "requester_ip": "10.0.0.8"
  },
  "mode": "服务端使用指定代理"
}
```

前端把 `initiator` 整块显示出来，可以直接比对「是不是服务器在测」。

UI 也改成浏览器代理面板的样子：**协议下拉**（`socks5` / `socks4` / `http` / `https`）
\+ 主机 / 端口 / 用户名 / 密码 四个输入框，下方实时预览拼好的地址（口令掩码）。
保存时按协议分流到 `SOCKS_PROXY` / `HTTP_PROXY` / `HTTPS_PROXY`。
