# 18 防未来数据泄漏规范

一句话定位：规定「任意时点的判断只能使用该时点已存在的数据」，并在回测、回放、指标三条代码路径上分别落地了具体的因果性保证。

## 代码位置

| 文件 | 关键位置 | 因果性处理 |
| --- | --- | --- |
| `backend/app/services/backtest_service.py` | `_simulate()` 134-149 行、77-94 行、238-242 行 | 逐日推进；ATH/分位/MA200 用 `closes[:i+1]`；恢复天数不用全局峰值 |
| `backend/app/services/replay_service.py` | 46-89 行、141-238 行、240-270 行 | 先倒序取最近 N 根再翻转；截断到回放日；滞后 > 3 天直接拒答；上下文表按 `<=` 目标时间查询；事后视角单独隔离 |
| `backend/app/engines/indicators.py` | `sma/ema/rsi/macd/atr/bollinger/realized_volatility` | 全部为滚动窗口函数，窗口内不含未来点 |
| `backend/app/engines/forecast.py` | 43-52 行 | 特征在 `i`，标签在 `i + horizon_days`，只取 `i` 之前的信息构造特征 |
| `backend/app/engines/cycle.py` | `_find_similar_periods()` 187-220 行 | 注释声明「只用该时点之前的信息」，用 `closes[:i+1]` 求历史 MA200 与峰值 |
| `backend/app/services/strategies.py` | `StrategyContext` 注释 | context 字段必须来自决策时点已知数据，回测与实盘共用 |

## 实现口径

### 回测侧（`backtest_service.py`）

| 规则 | 代码事实 |
| --- | --- |
| 可见窗口 | `history = closes[: i + 1]`（135 行），`ath = max(history)`、`percentile = (history <= price).sum()/len × 100`、`ma200` 仅当 `len(history) >= 200` 才算 |
| 决策与成交同日 | 决策用第 `i` 根收盘价，买入也按同一根的收盘价 ×（1+滑点）成交，不偷看第 `i+1` 根 |
| 区间过滤 | `_filter_range()` 用 `start_ts <= ts < end_ts`；`end_ts` 为指定日期 + 1 天 |
| 回撤基准 | `max_dd_peak_value = dd_start_equity`，即「本次回撤起点对应的峰值」，代码注释明确「绝不使用事后才知道的全局最高权益，避免隐性未来函数」 |
| 恢复判定 | 只在 `ts > max_dd_trough_ts` 且权益 ≥ 该次起点峰值时判定恢复（238-242 行） |
| 版本绑定 | `data_version = "{count}bars_{start_ts}_{end_ts}"`，`model_version = "bt_v1"` 一同入库 |
| 拒绝短样本 | 区间内 < 60 根日线直接返回 `ok=False` |

### 回放侧（`replay_service.py`）

| 规则 | 代码事实 |
| --- | --- |
| 查询顺序（关键坑） | 代码注释：必须 `order_by(desc(Candle.ts)).limit(3000)` 再 `reverse()`；若写成 `order_by(ts).limit(N)` 会取到「历史上最早的 N 根」，回放 2021-11 会实际算到 2021-06 |
| 时间上界 | `Candle.ts <= target_day_end`（回放日 + 86400），取回后再二次过滤 `ts <= target_day_end` |
| 滞后校验 | `lag_days = (target_day_end - 最后一根 ts) // 86400`，`> 3` 天直接返回 `available=False`，并给出 `local_latest_date` / `lag_days`，文案明确「系统不会用更早的数据冒充回放日」 |
| 上下文表 | `Sentiment / OnchainMetric / MacroSeries` 按 `observation_ts <= target_ts` 取最近 1 条（宏观 60 条）；`Derivative` 按 `observation_time <= 目标时刻`；全部倒序取第一条 |
| 时间线 | `TimelineEvent.ts.between(target_ts ± 30 天)`——**这是唯一允许跨越回放日的查询**，事件本身带 `date`，前端需自行分辨事件发生在回放日之前还是之后 |
| 事后视角隔离 | 仅当 `perspective == "aftermath"` 才调用 `_aftermath()`，并把 `note` 覆盖为「事后视角……不能用来评价当时决策的对错」；结果附 `warning: 这是事后才知道的结果` |
| 声明 | 默认 `note`：「以上所有数值均来自「当时已经存在」的数据，未使用任何未来信息。」 |

### 指标侧（`indicators.py`）

| 保证 | 代码事实 |
| --- | --- |
| 滚动窗口 | `sma` 从第 `window-1` 个点才有值；`bollinger` 的 `std` 循环从 `window-1` 开始；`realized_volatility` 从 `window` 开始 |
| 递归指标 | `ema` / `rsi` 只依赖当前点与上一状态，天然向前 |
| 回填语义 | `atr` 的 `true_range` 首根用自身 close 作 prev，不引入后一根数据 |
| 序列输出 | `to_series()` 与 ts 一一对应，不做前后填充；`nan/inf` 直接跳过而非插值 |

### 预测侧（`forecast.py`）

特征在 `i`（`ma200`、`peak`、`ret30`、`vol` 都只用 `closes[:i+1]`），标签是 `i + horizon_days` 的收益；当前状态用序列末尾计算，不混入未来。

## 与其它模块的关系

- `plan_service.next_contribution()` 与回测共用 `multiplier_for()`，因此「今天该投多少」与「历史上当时会投多少」遵循同一规则（见文档 16、17）。
- `replay_service` 复用 `IndicatorEngine / ValuationEngine / CycleEngine / RiskEngine`，靠「传入已截断的 K 线」而不是靠引擎内部开关来保证因果性。
- 数据版本（`data_version`）与模型版本（`model_version`）一起写进 `BacktestRun`，任何一次回测都能追溯到当时的数据覆盖范围（见文档 20）。
- 宏观 Provider 侧另有 observation_date / release_date 的区分约定（`backend/app/providers/impl/macro.py` 文件头），与本规范同向。

## 已知局限 / 注意事项

1. **回放的估值/周期/风险参数少于实盘**：`replay_service` 只给 `ValuationEngine.evaluate(latest, {})`（MVRV 恒缺失）、`CycleEngine.analyze(latest, valuation_state=...)`（无情绪、无资金费率）、`RiskEngine.analyze(latest, valuation_state=...)`（无资金费率、无宏观、链上不可用）。因此回放里的风险/周期分与当时实盘会跑出的分数**并不相同**，不能认为回放完全复刻了当时系统的输出。
2. **回放没有传入 ETF 资金流与情绪的「当日重算」**：情绪取的是「不晚于回放日的最近一条观测」，若采集有间隔，`observation_ts` 可能早于回放日很多天（返回值中带 `observation_ts`，前端应展示）。
3. **时间线事件跨窗口**：`timeline_nearby` 覆盖回放日 ±30 天，其中晚于回放日的事件属于未来信息，虽与 `aftermath` 分开存放，但混在同一数组里，展示时未按「之前/之后」分组。
4. **回测不做缺口检测**：区间内若存在缺失交易日，`i % step_days == 0` 的投入节奏会沿缺失后的索引错位，且不会给出提示。
5. **回测的样本外不是滚动推进**：`oos_result` 用 `initial_state=None` 重新起算，不构成真正的 walk-forward（详见文档 17 风险项）。
6. **`cycle._find_similar_periods()` 输出未来收益**：该函数返回 `return_30d_pct / return_90d_pct`，属于事后结果；当前两个调用点都没传 `candles`，所以线上恒为空数组——一旦接入，必须放在事后视角区展示。
7. **指标引擎本身不做「当前时间」校验**：它只按传入数组计算。调用方若误传未截断数据，无法被引擎察觉。
8. 当前**未提供**：自动化的未来函数检测（如逐点打乱时间戳做对抗测试）、回测与实盘结果的一致性对账、以及把「当时系统实际输出」落库用于事后核对的机制（`market_regimes` 表已在 `regime.py` 注释中被建议写入，但引擎内无写库代码）。
