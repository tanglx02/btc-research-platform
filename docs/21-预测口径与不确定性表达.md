# 21 预测口径与不确定性表达

一句话定位：用「历史相似状态的最近邻样本」给出未来一段时间的涨跌概率分布与 p10-p90 区间，样本或一致性不足时直接拒绝输出，绝不给出点位承诺。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `backend/app/engines/forecast.py` | `ForecastEngine.forecast()`、`_refuse()`、常量 `MIN_SAMPLES / MIN_CONSISTENCY` |
| `backend/app/services/market_service.py` （341-345 行） | `forecast(horizon_days=30)`，读取本地最近 5000 根日线后调用引擎 |
| `backend/app/api/market.py` （77-79 行） | `GET /market/forecast`，`horizon` 经 `Query(30, ge=7, le=365)` 校验 |
| `backend/app/db/model_registry.py` （`forecast_v1`） | 模型档案、有效条件与失效条件 |

## 实现口径

### 常量与入参

| 名称 | 值 / 默认 | 含义 |
| --- | --- | --- |
| `MODEL_VERSION` | `forecast_v1` | 写入每次输出的 `model_version` |
| `MIN_SAMPLES` | 30 | 可用样本下限 |
| `MIN_CONSISTENCY` | 0.35 | 一致性下限 |
| `horizon_days` | 30 | 预测周期（接口允许 7-365） |
| `max_samples` | 5000（关键字参数） | 签名中存在，**函数体内未使用** |
| K 线数量门槛 | `n >= MIN_SAMPLES + horizon_days + 250` | 即默认 30 天周期需 ≥ 310 根日线 |

### 计算流程（`forecast()`）

| 步骤 | 实现 |
| --- | --- |
| 1. 样本构造 | 对 `i in [200, n - horizon_days)`，用 `closes[:i+1]` 求 `ma200`（200 日均值）与 `peak`，得到特征 `(dev, dd, ret30, vol)`；`vol = std(diff(log(closes[i-30:i+1])))`；标签为 `(closes[i+horizon] - closes[i]) / closes[i]` |
| 2. 当前状态 | `cur_ma200 / cur_peak / cur_dev / cur_dd / cur_ret30 / cur_vol`（仅用序列末尾） |
| 3. 相似度 | 按特征标准差归一化后的欧氏距离（注释称「马氏距离的简化版」）：`dist = sqrt(sum(((X - cur)/scale)^2))` |
| 4. 邻域 | `k = min(int(len(targets) × 0.15), 200)`，再 `k = max(k, MIN_SAMPLES)`；取距离最小的 k 个标签 |
| 5. 一致性 | `consistency = mean(|samples - mean(samples)| < 0.25)`；`< 0.35` 直接 `_refuse()` |
| 6. 概率 | `up = mean(samples > 0.05) × 100`，`down = mean(samples < -0.05) × 100`，`flat = max(0, 100 - up - down)`（阈值 ±5%） |
| 7. 区间 | 对样本取 `p10/p25/p50/p75/p90`，换算为 `price_now × (1 + p)`，四舍五入到整数 |

### 输出体

成功时：`available=True / horizon_days / current_price / probabilities{up, flat, down} / expected_return_pct / range{p10, p25, median, p75, p90} / sample_count / consistency / data_range{start_ts, end_ts, bars} / model_version / uncertainty[] / disclaimer`。

`uncertainty` 固定三条：历史相似不代表因果（统计类比，不是因果模型）；加密市场受政策、流动性与突发事件影响，小概率事件频发；样本内相似度高不等于样本外同样有效。

拒答时 `_refuse(reason)` 返回：`available=False / reason / message: "当前无法可靠预测" / model_version / disclaimer: "系统宁可不给结论，也不用没有统计依据的数字误导用户。"`。

### 拒答的三种触发条件

1. 日线根数 `< MIN_SAMPLES + horizon_days + 250`：提示「历史数据不足（仅 N 根，至少需要 M 根）」。
2. 构造出的标签数 `< 30`：提示「可用历史样本不足（N 个）」。
3. `consistency < 0.35`：提示「历史相似样本结果过于分散（一致性 X），当前无法可靠预测」。

## 与其它模块的关系

- 输入完全来自本地 `candles` 表（`latest_candles(limit=5000)`），预测过程不请求第三方、不使用链上/情绪/衍生品数据。
- 与周期引擎（文档 14）互补：周期描述「现在在哪」，预测给出「未来区间分布」；两者都不是买卖指令。
- 版本与有效/失效条件登记在 `model_registry.py` 的 `forecast_v1` 档案，经 `GET /research/models` 暴露。
- 特征构造严格在 `i` 处、标签在 `i+horizon`，与文档 18 的因果性规范一致。

## 已知局限 / 注意事项

1. **只给概率与区间，不给点位承诺**：输出中没有任何「目标价 / 必涨 / 抄底 / 逃顶」字段，`disclaimer` 明确「仅为历史统计分布的概率描述，不构成投资建议」。文件名与注释也写明「禁止假装精准」。
2. **唯一的点估计是 `expected_return_pct`**（样本均值 × 100）。它是分布均值而非承诺值，但前端若单独突出这个数字，容易被读成「预期涨 X%」——**建议与 `range` 和 `consistency` 同屏展示**，这是本模块唯一需要警惕的呈现风险。
3. **付费数据源无关**：本引擎不使用任何付费 API；所有依赖都是本地日线。**但**它也不因此更准——不使用链上/情绪/资金流意味着特征维度只有 4 个价格衍生量。
4. 样本量门槛换算：`horizon_days=365` 时需要 ≥ 645 根日线；`market_service` 只取 5000 根，长期预测的历史纵深有限。
5. **一致性检查用的是绝对阈值 0.25**（25% 收益偏差内算「一致」），在高波动环境下几乎所有样本都落在带内，`consistency` 可能虚高；反之低波动期容易整体拒答。阈值是人工设定、未做敏感性检验。
6. **`k` 的下限 `max(k, MIN_SAMPLES)`**：即便 `len(targets) × 0.15 < 30`，也会强制取 30 个最近邻，等于把较远（不相似）的样本拉进来，可能稀释相似性。
7. **`max_samples=5000` 参数未使用**：函数体内没有任何引用，属死参数。
8. **区间值取整到元**（`round(..., 0)`）：BTC 价格量级下精度足够，但低价位资产复用时会失真。
9. **`p50/median` 与 `probabilities` 可能不自洽**：`flat` 是按 ±5% 阈值统计的，与区间分位数是两套口径，同屏展示时不要互相推导。
10. **未做覆盖度检验**：档案中 `oos_validated / walk_forward / parameter_sensitivity` 全为 `False`，计划中的「滚动预测并统计真实结果落在 p10-p90 内的比例」尚未实现。当前**未提供**任何预测准确率的统计口径或历史命中率展示。
11. 近邻法对「从未出现过的市场环境」失效——档案 `fail_when` 明确写了这一点，但引擎本身没有检测机制，仍会返回一个相似度看似合理的区间。
12. 当前**未提供**：多周期联合预测、预测结果的落库与事后核对、以及预测区间随时间的更新轨迹。
