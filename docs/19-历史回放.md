# 19 历史回放

一句话定位：给定任意历史日期，用「当时已经存在的数据」重建当时的指标、估值、周期、风险与上下文，并可选地对照展示事后结果。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `backend/app/services/replay_service.py` | `ReplayService`（`replay()` / `_context_at()` / `_aftermath()`） |
| `backend/app/api/research.py` （39-50 行） | `POST /research/replay`、`GET /research/replay`（`perspective` 正则限定 `then|aftermath`） |
| `backend/app/api/schemas.py` （`ReplayRequest`） | `date` 必填、`perspective` 默认 `then` |
| `backend/app/engines/` | `IndicatorEngine / ValuationEngine / CycleEngine / RiskEngine` 被直接复用 |
| `backend/app/db/models.py` | `Candle / Sentiment / Derivative / OnchainMetric / MacroSeries / TimelineEvent` |

## 实现口径

### `ReplayService.replay(date_str, perspective="then")`（`MODEL_VERSION = "replay_v1"`）

| 步骤 | 实现 |
| --- | --- |
| 目标时刻 | `target_ts` = 日期按 UTC 零点；`target_day_end = target_ts + 86400` |
| 取 K 线 | `select(Candle).where(symbol=BTC, interval=1d, ts <= target_day_end).order_by(desc(ts)).limit(3000)`，再 `reverse()` 成升序 |
| 二次截断 | 取回后再过滤 `ts <= target_day_end` |
| 滞后校验 | `lag_days > 3` 时返回 `available=False` + `local_latest_date` + `lag_days`，提示先执行 `btcctl.py backfill` |
| 快照 | `snapshot_price`、``ath_then = max(closes)`、`drawdown_pct`、`price_percentile_then`（在截断序列内算）、`data_provider` |
| 引擎链 | `IndicatorEngine.compute(candles)` → 补 `price_percentile`、`volume_latest` → `ValuationEngine.evaluate(latest, {})` → `CycleEngine.analyze(latest, valuation_state=...)` → `RiskEngine.analyze(latest, valuation_state=...)` |
| 上下文 | `await self._context_at(target_day_end)` |

返回体字段：`available / date / perspective / model_version / snapshot / indicators{latest, meta} / valuation / cycle / risk / sentiment / derivatives / onchain / macro / timeline_nearby / data_availability / note`；`perspective == "aftermath"` 时额外挂 `aftermath` 并替换 `note`。

### `_context_at(target_ts)` 的取数规则

| 模块 | 查询 | 返回 |
| --- | --- | --- |
| `sentiment` | `observation_ts <= target_ts` 倒序取 1 条 | `{available, index, classification, observation_ts, provider}` 或 `{available: False, message: "当时没有采集到情绪数据"}` |
| `derivatives` | `observation_time <= 目标时刻` 倒序取 1 条 | `funding_rate / funding_annualized_pct / open_interest / provider / observation_time`，否则 `available: False` |
| `onchain` | `observation_ts <= target_ts` 倒序取 **20 条** | `{available, metrics: {metric: value}, provider}` |
| `macro` | `observation_ts <= target_ts` 倒序取 **60 条**，按 `series_id` 去重（`setdefault` 保留第一条，即最近的） | `{available, series: {series_id: {value, ts, provider}}}` |
| `timeline` | `ts between(target_ts - 30d, target_ts + 30d)` 升序 | `{date, type, title, impact}` 列表 |
| `availability` | 上述四项是否取到 | `{sentiment, derivatives, onchain, macro}` 布尔 |

### `_aftermath(candles, from_ts)`

- 读取本地最多 10000 根日线，过滤 `ts > from_ts` 得到未来段。
-  horizons 固定为 `30d / 90d / 180d / 365d`，`idx = min(days, len(futures)-1)`；数据不够时返回 `{price: None, return_pct: None, note: "本地数据尚未覆盖该区间"}`。
- 另给 `max_gain_pct`（未来最高价相对基准）、`max_loss_pct`（未来最低价）、`days_available`、`perspective: "aftermath"`、`warning: "这是事后才知道的结果，实盘当时无法预知。"`

## 与其它模块的关系

- 复用四个引擎，保证「回放里看到的指标」与「实盘首页看到的指标」是同一套公式（文档 13、14、15）。
- 与回测（文档 17）互补：回放重演**某一个时点的判断**，回测重演**一整段区间的资金曲线**。
- 因果性保证的具体实现见文档 18；本文件只描述功能口径。
- 数据缺口由数据质量模块与 `btcctl.py backfill` 负责（回放的拒答文案直接指向该命令）。

## 已知局限 / 注意事项

1. **本地数据不足时直接拒答**：`lag_days > 3` 就返回 `available=False`，不提供任何降级结果——系统不会用更早的数据冒充回放日。
2. **回放的估值恒缺 MVRV**：`ValuationEngine.evaluate(latest, {})` 传的是空字典，因此回放结果里 `missing_factors` 必然包含 MVRV。MVRV 依赖付费链上 Provider（`GLASSNODE_API_KEY` / `CRYPTOQUANT_API_KEY`），未配置时**不提供任何数据、不用假数据顶替**；回放路径即使配置了也不会读取。
3. **回放的周期/风险维度比实盘少**：两个引擎调用都没传 `sentiment_index / funding_annualized / macro / onchain_available`，即使 `_context_at()` 取到了这些数据也没有回填给引擎。结果是：回放里的风险分只由趋势+估值+波动（+可能缺失的流动性）构成，杠杆/宏观/链上三个维度恒为 `available=False`。
4. **`onchain` 的 provider 只取第一条**：`provider` 取 `onchain_rows[0].source_id`，若 20 条来自不同来源，其余来源不会体现。
5. **`macro` 按 `series_id` 去重后只保留最近一条**，没有序列曲线，无法在回放里看宏观走势。
6. **时间线跨越回放日**：`timeline_nearby` 包含回放日之后 30 天的事件，属于未来信息；返回体未按「之前/之后」分组，前端若直接铺开会造成泄漏。
7. **`_aftermath` 的 horizon 近似**：`idx = min(days, len(futures)-1)`，未来段不足时会用「最后一根」冒充 30/90/365 天的位置（不返回 None），只有完全没有未来数据时才标 `note`。
8. **`_aftermath` 重新查库**：它用 `latest_candles(limit=10000)` 重新读取全量，而不是复用已加载的 `candles`，两次查询之间若数据被回填会不一致（概率低但存在）。
9. `IndicatorEngine.compute()` 在回放中默认 `include_series=True`，会为最多 3000 根生成多条序列，响应体较大；API 层没有开关控制。
10. 当前**未提供**：回放结果的落库/对比、同一日期多次回放的差异记录、回放视角下 ETF 资金流（`_context_at` 不查 ETF 表）、以及「当时系统实际输出 vs 现在重算输出」的对账。
