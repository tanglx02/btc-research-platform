# 12 问答助手与可追溯设计

一句话定位：页面上任何一个数字，都必须能一路展开到原始返回值；问答助手的回答也**只基于真实数据**，不编造。

## 一、可追溯设计

### 核心原则

> 浏览器上可见即可追源到原始 JSON。

不是「展示一个结论」，而是「结论 + 这个结论从哪来 + 原始数据长什么样」。

### 前端三个渲染组件

定义在 `frontend/static/js/core.js`：

| 组件 | 作用 |
| --- | --- |
| `rawBlock(title, obj)` | 原始数据折叠块：把任意对象 JSON 序列化展示。任何结论都必须能一路展开到这里 |
| `sourceBlock(src)` | 来源声明块：显示 provider 名称、是否切换备用源、质量徽章、置信度、响应耗时、数据观测时间、切换原因 |
| `crossValidationBlock(...)` | 交叉验证块：多源一致/冲突的展示 |

页面渲染异常时，也会调用 `rawBlock` 把原始上下文展示出来，而不是只报一句「加载失败」。

### 来源块展示的内容

| 字段 | 说明 |
| --- | --- |
| 来源 | `display_name` 或 `provider`；切换过则显示「已切换备用源」徽章 |
| 质量 | 质量徽章（`VERIFIED` / `SINGLE_SOURCE` / `STALE` / `CONFLICT` 等） |
| 置信度 | 百分比 |
| 响应 | 耗时 ms |
| 数据时间 | 观测时间 + 「多久之前」 |
| 切换原因 | `failover_reason`（若发生过切换） |

### 后端支撑

- `raw_market_data` 表保存原始响应留痕。
- `provider_requests` / `provider_failover_events` 记录请求与切换。
- API 返回体中统一带 `source` 字段（含 `provider`、`quality`、`used_fallback`、`latency_ms`、`observation_time`）。

### 绝不隐藏降级

数据状态必须由 API 与前端**显式呈现**。降级运行时顶栏显示 `降级运行：显示最后可信数据`，不允许悄悄用旧数据冒充实时数据。

## 二、问答助手

### 代码位置

`backend/app/api/assistant.py`

### 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/v1/assistant/ask` | 提问（解释数据 / 指标 / 模型 / 历史 / 回测） |
| GET | `/api/v1/assistant/indicator-help/{code}` | 指标通俗解释 |

### 回答生成流程

```
_build_context()
  ├─ MarketService.current_price()
  ├─ MarketService.indicators(limit=500)
  ├─ MarketService.analysis()
  ├─ MarketService.sentiment()
  └─ MarketService.derivatives()
      ↓  （任一环节失败只记日志，不导致助手不可用）
  _rule_based_answer(question, ctx)     # 基于真实数据的规则解释
      ↓  （若启用 LLM 且配置 Key）
  _llm_answer(question, ctx)            # 可选增强，失败则回退规则答案
```

### 设计约束

| 约束 | 落地 |
| --- | --- |
| **不编造** | 规则答案只从 `ctx` 中的真实字段取值，没有就说没有 |
| 上下文缺失不雪崩 | `_build_context()` 内部 try 包裹，部分缺失只记 `assistant.context_error` |
| LLM 可选 | 未配置 `OPENAI_API_KEY` 时只用规则答案；LLM 失败自动回退 |
| 带来源 | 回答附 `facts`，每条事实带来源 |

### 相关配置

```
AI_ASSISTANT_ENABLED=true
OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
```
