# 17 策略回测与准确性验证

一句话定位：按日逐根推进地模拟「定期投入 + 策略倍数」的效果，输出收益、回撤、恢复时间等统计，并把每次结果连同模型版本与数据版本永久入库。

## 实现口径

| `strategy_params` | `{}` | |

| `slippage` | 0.0005 | 同上 |
| `max_single_contribution` / `cash_reserve` | 0.0 | |

| `oos_split` | 0.3 | |
| `name` | `""` | 缺省回退为 `f"{strategy_code} {日期}"` |

### `BacktestEngine.run(config)`（`MODEL_VERSION = "bt_v1"`）

1. 读取本地最多 10000 根日线；无数据返回 `{"ok": False, "message": "本地没有历史数据..."}`。
2. `_filter_range()` 按 `start_date/end_date` 过滤（`end_ts` 含 `+1 天`）；区间内不足 **60 根**直接拒绝并报出实际根数。
3. 非 `insample` 时：`split_idx = max(30, int(len × (1 - oos_split)))`，训练段 `candles[:split_idx]`、测试段 `candles[split_idx:]`；结果附 `validation{mode, train_days, test_days, train_period, test_period, note}` 与 `oos_result`。
4. `_persist()` 写入 `BacktestRun` + `BacktestResult`，`data_version = "{count}bars_{start_ts}_{end_ts}"`，`model_version = "bt_v1"`，`status="done"`；`equity_curve` 只保留最后 4000 个点。

### `_simulate()` 循环要点

| 步骤 | 实现 |
| --- | --- |
| 可见窗口 | `history = closes[:i+1]`，逐日重算 `ath`、`drawdown_pct`、`ma200`（≥200 根才给）、`percentile` |
| 投入节奏 | `step_days = 7`（weekly）或 `30`（monthly），`i % step_days == 0` 时投入 |
| 倍数 | `multiplier_for(strategy_code, strategy_params, ctx)`，结果裁剪到 `[0, 10]` |
| 首日建仓 | `i == 0 且 cash > 0` 时一次性买入 `cash - cash_reserve` |
| 成交 | `exec_price = price × (1 + slippage)`，`fee = to_buy × fee_rate`，`btc += (to_buy - fee) / exec_price` |
| 单笔上限 | `injected = min(base × multiplier, max_single_contribution)`（后者 > 0 时） |

输出字段：`final_value / total_invested / net_profit / roi / cagr / max_drawdown / max_drawdown_window{start_ts, trough_ts, duration_days} / recovery_days / recovery_note / sharpe / sortino / volatility / best_year / worst_year / btc_amount / avg_cost / final_price / total_fees / trades / initial_price / days / years / equity_curve / monthly_returns / warnings / buy_and_hold`。

- `_risk_metrics()`：基于月度收益，`sharpe = mean/std × sqrt(12)`，`sortino = mean/downside_std × sqrt(12)`，`volatility = std × sqrt(12) × 100`；月度样本 < 3 时全部返回 0。
- `warnings` 规则：区间 < 365 天提示代表性有限；`trades < 30` 提示样本少；`max_drawdown < -70` 提示确认风险承受能力。
- `buy_and_hold` 只用 `initial_capital` 折算，不含定投部分。

## 与其它模块的关系

- 回测与 `PlanService.next_contribution()` 共用 `multiplier_for()`，保证「建议金额」与「回测模拟」是同一套规则。
- `POST /market/plan/{plan_id}/simulate-plan` 把用户计划转成 `BacktestConfig`（见文档 16）。
- `GET /research/models` 展示 `bt_v1` 档案；`GET /research/backtest/runs` 列出历史运行及其 `model_version` / `data_version`。
- 数据来源完全本地（`latest_candles` + `candle_coverage`），回测过程不请求任何第三方接口。

## 已知局限 / 注意事项

1. **两个策略在回测中永远退化为固定定投（重大风险项）**：`_simulate()` 构造 `StrategyContext` 时只填了 `ts / price / drawdown_pct / ath / price_percentile / ma200 / cash_balance`，**没有填 `risk_level` 与 `cycle_phase`**，因此 `dca_risk` 与 `dca_cycle` 在回测里恒返回 1.0，与 `dca_fixed` 结果完全相同。策略清单里它们仍被展示为可选策略。
2. **`walk_forward` 名不副实（风险项）**：`validation_mode="walk_forward"` 与 `oos` 走的是同一段代码，只做**一次**训练/测试切分并各跑一遍，没有滚动窗口、没有多折、没有参数重估。档案 `bt_v1` 中 `walk_forward: True` 与实现不符。
3. **样本外段是独立重跑**：`oos_result = self._simulate(test_slice, config, initial_state=None)`，测试段从 `initial_capital` 重新开始、持仓不延续，因此它不是「训练段结束后继续跑」的真实推进，样本外收益不含训练段积累的仓位。
4. `split_idx = max(30, ...)` 的下限可能在极短区间上把训练段压到 30 根，而整体下限 60 根只保证总量，训练/测试段各自可能过短。
5. **参数敏感性分析当前未提供**：没有网格搜索、没有参数敏感性输出（档案中 `parameter_sensitivity: False`，仅列为计划）。
6. `max_drawdown` 的恢复天数 `recovery_days` 只在**回测区间内**查找，未恢复时 `recovery_days = 0` 且 `recovery_note` 写明「截至回测结束仍未回到该次回撤前的高点」——0 天不等于「立刻恢复」，前端不能只读数字。
7. `buy_and_hold` 对照只折算 `initial_capital`，不含每期定投，与 `final_value` 不是同一投入口径，直接对比会高估或低估。
8. 成交假设偏简化：全部按收盘价 ×（1+滑点）成交，没有盘口深度、没有部分成交、没有卖出逻辑（`_simulate` 中**没有实现任何卖出/止盈/止损分支**）。
9. `cagr` 在 `total_invested > 0` 且 `years > 0` 时才有意义；多次投入的时间加权收益未用 IRR，用 `final/invested` 开方近似，会与真实年化有偏差。
10. Sharpe/Sortino 用月度收益且**无风险利率按 0 处理**，月度样本少于 3 时返回 0（不是 `None`），容易被误读为「风险调整后收益为零」。
11. 回测完全依赖本地 K 线覆盖：区间内有缺口不会报错，只由数据质量模块另行提示。
12. 当前**未提供**：策略参数优化、批量参数扫描、回测结果的前端对比视图接口、以及回测准确性（预测 vs 实际）的统计校验。
