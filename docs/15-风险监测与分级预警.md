# 15 风险监测与分级预警

一句话定位：从趋势、估值、波动、杠杆、流动性、宏观、链上七个维度独立打分，加权合成 0-100 的风险总分并映射为五级，每个维度都必须交代「用了什么数据、缺了什么数据」。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `backend/app/engines/risk.py` | `RiskEngine.analyze()` 与分级常量 `LEVELS`、`level_of()` |
| `backend/app/services/market_service.py` （315-321 行） | 实盘装配，传入估值状态、资金费率年化、宏观、链上可用性 |
| `backend/app/services/replay_service.py` （103 行） | 回放装配，仅传入估值状态 |
| `backend/app/engines/regime.py` （67 行） | 消费 `risk["level"]` 生成 `risk_state` |
| `backend/app/db/model_registry.py` （`risk_v1`） | 模型档案与失效条件 |

## 实现口径

### 分级（`risk.py` 14-27 行）

| 分数区间 | code | 中文 |
| --- | --- | --- |
| 0 - 20 | `low` | 低风险 |
| 20 - 40 | `moderate` | 中等 |
| 40 - 60 | `elevated` | 偏高 |
| 60 - 80 | `high` | 高风险 |
| 80 - 100 | `extreme` | 极高风险 |

`level_of(score)` 按 `score < high` 命中，≥100 兜底为 `extreme`。

### 七个维度

| 维度 | 可用条件（`availability`） | 打分口径 | 不可用时的处理 |
| --- | --- | --- | --- |
| `trend` | 有 `price` 且 `ma200` | 基准 40；价格 < MA200 `+25`，> MA200 `-15`；回撤 < -60% `+15`，< -30% `+8`；截断到 [0,100] | 基准 40 且 `available=False` |
| `valuation` | 传入了 `valuation_state` | 映射表：`deep_undervalue 5 / undervalue 15 / fair 40 / overvalue 65 / extreme_overvalue 85`，未知状态取 40 | 40 分，原因写「估值数据不可用，该维度使用中性默认值且不参与重点加权」 |
| `volatility` | `indicators["volatility_30d"]` 非空 | `min(100, max(0, 30 日年化波动率 × 1.6))` | 40 分，原因「波动率数据不足」 |
| `leverage` | `funding_annualized` 或 `open_interest_usd` 任一非空 | `min(100, max(0, (资金费率年化 - 5) × 2.2))`；> 40% 追加「多头杠杆拥挤」提示 | 30 分，原因「衍生品数据源不可用，杠杆维度按不可知处理」 |
| `liquidity` | `indicators["volume_latest"]` 为真 | 只要拿到成交量就固定 30 分，不做量能比较 | 40 分，原因「未获取到成交量数据，流动性风险按中性处理」 |
| `macro` | `macro.dxy` 或 `macro.us10y` 存在 | 基准 40；`us10y >= 4.5` `+15`，`us10y <= 3.0` `-10`；截断到 [0,100] | 40 分，原因「宏观数据源未配置或不可用」 |
| `onchain` | `onchain_available=True` | 固定 45 分，仅记录「链上基础数据可用」 | 40 分，原因「链上数据不可用，该维度不参与判断」 |

- 权重：`trend 0.20 / valuation 0.20 / leverage 0.15 / liquidity 0.10 / macro 0.15 / onchain 0.10 / volatility 0.10`（合计 1.00）。
- 合成公式（`risk.py` 159-160 行）：**只有 `available=True` 的维度参与加权**，分母为这些维度的权重之和，避免用默认值稀释真实信号。
- 输出：`overall_risk`、`level`、`level_cn`、`dimensions{score, level, level_cn, available, reasons[]}`、`data_availability`、`weights`、`model_version`、`note`（固定文案「风险评分描述当前环境的脆弱程度，不是对未来价格的预测。」）。

## 与其它模块的关系

- 上游依赖：指标引擎的 `price / ma200 / drawdown / volatility_30d / volume_latest`（文档 13）、`ValuationEngine` 的 `state`（文档 14）。
- 下游消费：`MarketRegimeEngine` 取 `risk["level"]` 作为 `risk_state` 并影响综合状态措辞；前端风险卡片展开各维度 `reasons`。
- 回放场景（`replay_service`）用同一引擎，但因只传 `valuation_state`，杠杆/宏观/链上/波动（回放里 `volatility_30d` 由指标引擎给出，可用）以外维度会退化为不可用。
- `market_service.analysis()` 中 `onchain_available=inputs["mvrv"] is not None`——链上维度是否可用**由 MVRV 是否取到决定**。

## 已知局限 / 注意事项

1. **付费数据源依赖**：链上维度与 MVRV 都依赖付费 Provider（`GLASSNODE_API_KEY` / `CRYPTOQUANT_API_KEY`）；衍生品依赖 Coinglass 等（`COINGLASS_API_KEY`）；宏观依赖 FRED（`FRED_API_KEY`）。**未配置时不提供任何数据**——对应维度置 `available=False`、不参与加权，并在 `reasons` 里写明原因；系统不会用假数据或历史均值顶替。
2. **可用维度过少时会低估风险**：外部源大面积不可用时只剩价格与波动两个维度，综合分被中性值拉平（档案 `fail_when` 已写明「可能低估真实风险」）。前端应同时展示 `data_availability`。
3. **`open_interest_usd` 只影响可用性，不参与打分**：`RiskEngine.analyze()` 接收该参数，但杠杆分只由 `funding_annualized` 计算；若只有 OI 没有费率，维度被标记为可用、分数却恒为默认 30。这是一个实现上的不一致（风险项）。
4. **流动性维度是常量**：只要取到成交量就是 30 分，没有与历史成交量的比较，实际区分度为零。
5. **链上维度也是常量**（45 分），不区分具体链上指标读数。
6. **档案与代码不一致（风险项）**：`model_registry.py` 中 `risk_v1` 声称「六维」并列出六个维度名，但代码权重表含 7 个维度（含 `trend`）。
7. **风险分不是预测**：高分不代表立刻下跌，低分也不代表安全（代码 `note` 与档案 `fail_when` 均已声明）。
8. 评分阈值（如波动 ×1.6、资金费率 `(x-5)×2.2`、`us10y` 4.5/3.0）为人工设定的经验值，未做参数敏感性或样本外检验（档案 `oos_validated / walk_forward / parameter_sensitivity` 均为 `False`）。
9. 当前**未提供**：预警推送/告警触发、风险等级随时间变化的记录表、风险分与后续真实回撤的对照统计（档案中仅列为「计划检验」）。
