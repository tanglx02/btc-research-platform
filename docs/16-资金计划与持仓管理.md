# 16 资金计划与持仓管理

一句话定位：让用户把自己的资金计划与真实交易记录进系统，算出持仓、平均成本与浮盈亏，并给出下一期投入建议金额——全程只做记录与模拟，不接交易 API、不会自动下单。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `backend/app/services/plan_service.py` | `PlanService`：计划 CRUD、交易账本、持仓计算、快照、下次投入建议 |
| `backend/app/api/portfolio.py` | 11 个 HTTP 端点（计划、策略、交易、持仓） |
| `backend/app/api/schemas.py` | `PlanRequest`、`TransactionRequest` 的字段与默认值、校验 |
| `backend/app/api/market.py` （98-134 行） | `POST /market/plan/{plan_id}/simulate-plan`：把计划转成回测配置 |
| `backend/app/db/models.py` | `UserPlan` / `UserTransaction` / `PortfolioSnapshot` |
| `backend/app/services/strategies.py` | `multiplier_for()` 提供投入倍数 |

## 实现口径

### 计划（`PlanService.create`，默认值为 `plan_service.py` 或 `PlanRequest` 中给出）

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `name` | 「我的 BTC 计划」 | — |
| `currency` | `CNY` | — |
| `initial_capital` / `monthly_income` / `monthly_contribution` / `weekly_contribution` | 0.0 | 金额类，接口校验非负 |
| `contribution_frequency` | `monthly` | 仅 `weekly` 分支会改用 `weekly_contribution` |
| `start_date` | 今天（UTC，`%Y-%m-%d`） | `end_date` 默认 `None` |
| `cash_reserve` / `max_single_contribution` | 0.0 | 0 表示不限 |
| `max_drawdown_tolerance` | 50 | 接口默认 50.0 |
| `strategy_code` | `dca_fixed` | 见文档 17 的策略表 |
| `strategy_params` | `{}` | 传给策略函数 |

`update()` 只覆盖 15 个白名单字段且跳过 `None`；`delete()` 返回布尔。

### 交易账本

- `add_transaction(plan_id, payload)`：`date` 缺省取今天；`price` 必填且必须 > 0（接口层校验）；`side` 默认 `buy`；`fee` 默认 0；`source` 默认 `manual`。
- 互补推导：`amount_btc <= 0 且 amount_fiat > 0` 时 `btc = fiat / price`；`amount_fiat <= 0 且 amount_btc > 0` 时 `fiat = btc × price`。
- `ts` 由 `date` 字符串按 UTC 零点换算；列表按 `ts` 倒序，`limit` 默认 500（接口允许 1-2000）。

### 持仓计算（`holdings()`）

遍历全部交易（按 `ts` 升序）：`buy` 累加 `amount_btc`、`invested += amount_fiat + fee`；`sell` 扣减 `amount_btc`、`realized += amount_fiat - fee`。

| 输出字段 | 口径 |
| --- | --- |
| `total_btc` | 买卖净额 |
| `total_invested` | 买入金额 + 买入手续费累计 |
| `realized_pnl` | 卖出金额 - 卖出手续费累计 |
| `avg_cost` | `invested / total_btc`（`total_btc > 0` 时） |
| `current_price` | 本地最新一根日线收盘价（`latest_candles(..., limit=1)`） |
| `market_value` / `unrealized_pnl` | `total_btc × price`；`market_value - total_btc × avg_cost` |
| `roi` | `(market_value - invested) / invested × 100` |
| `quality` | 有本地 K 线为 `VERIFIED`，否则 `MISSING` |

持仓结果固定附带 `note`：「默认手动记录，不接入任何交易 API，系统不会自动下单。」

### 下次投入建议（`next_contribution(plan_id)`）

1. 需要本地最近 500 根日线，不足则返回 `{"available": False, "message": "本地历史数据不足"}`。
2. 用这 500 根计算 `now_price`、`ath = max(closes)`、`drawdown_pct`、`percentile`（当前价在 500 根中的分位）。
3. 构造 `StrategyContext(ts, price, drawdown_pct, ath, price_percentile)` → `multiplier_for(strategy_code, strategy_params, ctx)`（倍数被裁剪到 `[0, 10]`）。
4. `suggested = base × multiplier`，若 `max_single_contribution > 0` 再取 `min`。
5. 下次投入日：有历史交易则取最近一笔日期 + 7 天（weekly）或 + 30 天（monthly），否则取 `start_date`。
6. 返回 `base_amount / multiplier / suggested_amount / next_date / reason{drawdown_pct, price_percentile, strategy}` 与 `disclaimer`（「仅供参考，不构成投资建议」）。

## 与其它模块的关系

- `next_contribution` 与回测共用 `strategies.multiplier_for()`，保证「建议金额」与「回测结果」同源（见文档 17）。
- `snapshot()` 把持仓结果写入 `PortfolioSnapshot` 表，供后续净值曲线使用。
- `POST /market/plan/{plan_id}/simulate-plan` 把 `UserPlan` 字段映射为 `BacktestConfig`（`initial_capital / monthly_contribution / weekly_contribution / contribution_frequency / start_date / end_date / strategy_code / strategy_params / max_single_contribution / cash_reserve / validation_mode`），回测结果再挂上 `plan` 信息返回。
- 持仓估值只用本地 K 线收盘价，不调用任何行情 Provider。

## 已知局限 / 注意事项

1. **不接交易 API**：`holdings()` 的 `note` 明确「不接入任何交易 API，系统不会自动下单」；所有交易必须手工录入，`source` 默认 `manual`。当前**未提供**交易所同步、自动定投执行、券商/交易所 OAuth 绑定。
2. **平均成本口径偏乐观**：`avg_cost = 累计买入金额 / 当前持有 BTC`，卖出时**不扣减已投入成本基数**，因此有卖出记录后 `avg_cost` 会被系统性抬高、`unrealized_pnl` 相应偏低（未实现/已实现盈亏可能重复或错位）。
3. **多个未使用的计划字段**：`monthly_income`、`cash_reserve`、`max_drawdown_tolerance`、`initial_capital`、`end_date` 都被存储与返回，但 `PlanService` 内部**没有任何计算使用它们**；其中 `cash_reserve` 与 `initial_capital` 只在转成回测配置时才生效。
4. `next_contribution` 的分位数只基于最近 500 根日线，与指标引擎的全历史分位（文档 13）不是同一口径，同一时点两处数值可能不同。
5. `holdings()` 使用 `latest_candles(limit=1)` 的最新收盘价，若本地数据未及时更新，`quality` 仍会显示为 `VERIFIED`（它只判断「有没有 K 线」），不会反映数据陈旧（`STALE`）。
6. `snapshot()` 每次调用都新增一行快照，且**未做同一天去重**——重复点击会写入多条同日记录。
7. `plan_service.py` 导入了 `UserHolding`，但代码中未使用；`UserHolding` 表本身在 `plan_service` 路径下没有读写。
8. `add_transaction` 若 `date` 不是 `%Y-%m-%d` 格式会抛 `ValueError`，接口层未做格式校验（只有 `price > 0` 的校验）。
9. 删除计划不会级联删除其交易记录；被删计划的交易会以 `plan_id` 悬空的形式保留，并继续计入不带 `plan_id` 的全局 `holdings()`。
10. 所有金额字段以 `currency`（默认 CNY）记账，但**没有汇率换算**：价格来自美元计价的 BTC 日线，成本却是用户录入的法币金额，两者混用在同一 `market_value` 中，未做币种转换。
