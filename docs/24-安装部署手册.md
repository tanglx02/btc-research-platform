# 24 · 安装部署手册

Windows 与 Linux 两套真实可用的安装、启动、守护与反代部署步骤；所有命令均来自 `scripts/` 下的实际实现。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `scripts/platformctl.py` | 唯一实现：install / update / uninstall / start / stop / restart / status / doctor / backup / restore / menu |
| `scripts/btcctl.py` | 业务运维：init-db / backfill / tick / health / probe / serve … |
| `scripts/backup.py` | 备份与恢复的实现（被 `btcctl backup/restore` 调用） |
| `scripts/windows/*.bat` | Windows 薄壳，转调 `platformctl.py` |
| `scripts/linux/*.sh` | Linux 薄壳，转调 `platformctl.py` |
| `scripts/linux/systemd/btc-platform.service` | systemd 单元（长期守护） |
| `scripts/linux/nginx/btc-platform.conf` | Nginx 反向代理 |
| `requirements.txt` | 依赖清单（Python 3.11+） |

关键路径（由 `platformctl.py` 常量决定）：仓库根 `ROOT`、虚拟环境 `ROOT/.venv`、配置 `ROOT/.env`、数据 `ROOT/data`、备份 `ROOT/backups`、日志 `ROOT/logs`、PID 文件 `ROOT/.runtime/server.pid`、默认端口 `8787`。

## 通用前置条件

| 项 | 要求 |
| --- | --- |
| Python | 3.11+（`find_system_python()` 会依次探测 3.13/3.12/3.11，找不到即退出，退出码 2） |
| 端口 | `.env` 中 `PORT`（默认 8787）未被占用；`start` 前会检测 |
| 网络 | 安装阶段需访问 PyPI；可用 `PIP_INDEX_URL` 环境变量指定镜像源 |
| 磁盘 | `data/`（SQLite 库）、`backups/`、`logs/` 需可写 |

## Windows 部署步骤

```bat
REM 1) 安装：创建 .venv / 生成 .env / 装依赖 / 初始化数据库
scripts\windows\install.bat
REM 可选参数（透传给 platformctl install）
scripts\windows\install.bat --upgrade --backfill --python C:\Python313\python.exe

REM 2) 后台启动（日志写入 logs\platform.log，PID 写入 .runtime\server.pid）
scripts\windows\start.bat --daemon

REM 3) 自检与状态
scripts\windows\doctor.bat
scripts\windows\status.bat
```

等价的命令行形式（不经过 .bat，效果完全相同）：

```bat
python scripts\platformctl.py install
python scripts\platformctl.py start --daemon
```

启动后访问：`http://127.0.0.1:8787/`、接口文档 `http://127.0.0.1:8787/docs`（生产环境 `APP_ENV=production` 时 `/docs` 关闭）。

交互菜单：`scripts\windows\menu.bat`（status / start / stop / health / backfill / gap-repair / backup / restore / update / doctor）。

守护方式说明：Windows 下 `--daemon` 使用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 启动 uvicorn，stdout/stderr 追加到 `logs/platform.log`；停止用 `taskkill /PID <pid> /T /F`。平台**没有**创建计划任务的实现，若需开机自启需自行在「任务计划程序」中配置。

## Linux 部署步骤

```bash
# 1) 赋予执行权限
chmod +x scripts/linux/*.sh

# 2) 安装（使用系统 python3 创建 .venv）
./scripts/linux/install.sh
./scripts/linux/install.sh --backfill      # 安装后直接回填历史（耗时较长，支持中断续传）

# 3) 后台启动与验证
./scripts/linux/start.sh --daemon
./scripts/linux/status.sh
./scripts/linux/doctor.sh
```

### systemd 守护（长期运行）

服务文件为 `scripts/linux/systemd/btc-platform.service`，其中路径 `WorkingDirectory`、`PATH`、`ExecStart`、`ReadWritePaths` 需按实际安装目录修改（示例为 `/opt/btc-platform`）：

```bash
# 0) 准备运行用户与日志目录（服务文件未包含建目录步骤，需人工执行）
sudo useradd -r -s /usr/sbin/nologin btc
sudo mkdir -p /var/log/btc-platform /opt/btc-platform
sudo chown -R btc:btc /opt/btc-platform /var/log/btc-platform

# 1) 安装单元
sudo cp scripts/linux/systemd/btc-platform.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now btc-platform
sudo systemctl status btc-platform

# 2) 常用运维
sudo systemctl restart btc-platform
sudo journalctl -u btc-platform -f
```

要点：`Type=simple` + 单进程 uvicorn；`Restart=always`、`RestartSec=5`；`EnvironmentFile=-/opt/btc-platform/.env`；`ProtectSystem=strict` 下用 `ReadWritePaths` 显式放开 `data`、`logs`、`backups`。

### Nginx 反向代理

```bash
sudo cp scripts/linux/nginx/btc-platform.conf /etc/nginx/sites-available/btc-platform
sudo ln -s /etc/nginx/sites-available/btc-platform /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

配置要点：后端只监听 `127.0.0.1:8787`；`/static/` 由 Nginx 直接返回并缓存 7 天；`/api/` 透传并注入 `X-Real-IP`/`X-Forwarded-For`/`X-Request-ID`，`proxy_buffering off`；`/api/v1/system/` 段额外做 IP 白名单（`allow 127.0.0.1; allow 10.0.0.0/8; allow 192.168.0.0/16; deny all;`）。

## install 实际执行的动作

`platformctl.py:cmd_install()` 依次完成（每一步失败立即中止并提示）：

1. 选择系统 Python（`--python` 指定或自动探测 3.11+）；
2. 创建 `data/`、`logs/`、`backups/`、`.runtime/`；
3. `ensure_env_file()`：`.env` 不存在则从 `.env.example` 复制；已存在则保留，并在 `ADMIN_TOKEN` 仍为默认值时给出 WARN；
4. `ensure_venv()`：创建 `ROOT/.venv`（已存在则跳过）；
5. `install_deps()`：`pip install -r requirements.txt`（`--upgrade` 时追加 `--upgrade`）；
6. `init_database()`：执行 `btcctl.py init-db`（建表 + 种子数据 + 打印各表行数）；
7. `--backfill` 时执行 `btcctl.py backfill`（失败不中断安装）。

## 已知局限 / 注意事项

- `platformctl` 默认使用仓库内的 `.venv`；本文中的测试与管理命令示例使用已验证环境 `C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe`（Windows）或 `.venv/bin/python`（Linux），两者需安装同一份 `requirements.txt` 才等价。
- systemd 单元默认以用户 `btc` 运行，且 `/var/log/btc-platform/` 必须事先存在，否则 `StandardOutput=append:` 会导致启动失败；服务文件未包含创建该目录或用户的步骤。
- Nginx 配置中的 HTTPS 段与 SSE 段均为注释示例，未启用；`server_name _` 需替换为真实域名。
- `--daemon` 启动的进程由 `.runtime/server.pid` 记录，若手动 kill 后未清理该文件，`status` 仍能通过 `pid_alive()` 判断；但端口被其他程序占用时 `start` 会直接失败并提示修改 `PORT`。
- `install` 是幂等的，可反复执行；但 `.env` 一旦生成不会被覆盖，新增配置项需手动同步。
- Windows 卸载脚本只删除 `.venv`，不会删除任何计划任务；`uninstall` 默认保留 `data/`、`.env`、`backups/`，只有 `--purge-data` 才删除（删除前强制备份）。
