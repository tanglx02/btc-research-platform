# 30 · 运维命令参考

`scripts/platformctl.py`（部署控制）与 `scripts/btcctl.py`（业务运维）的全部子命令、真实参数与行为。命令示例统一使用已验证环境：Windows 用 `C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe`，Linux 用 `.venv/bin/python`。

## 代码位置

| 文件 | 子命令数 | 入口 |
| --- | --- | --- |
| `scripts/platformctl.py` | 11（install/update/uninstall/start/stop/restart/status/doctor/backup/restore/menu）+ `--version` | `python scripts/platformctl.py <cmd>` |
| `scripts/btcctl.py` | 17（含 `serve`） | `python scripts/btcctl.py <cmd>` |
| `scripts/windows/*.bat`、`scripts/linux/*.sh` | 薄壳，参数原样透传 | 见「24 · 安装部署手册」 |

两个脚本都要求 `dest=command` 必填（`required=True`），未提供子命令时 argparse 直接报错退出。

## platformctl —— 部署控制

| 子命令 | 参数 | 行为要点 |
| --- | --- | --- |
| `install` | `--python PATH`、`--upgrade`、`--backfill` | 建目录 → 生成 `.env` → 建 `.venv` → `pip install -r requirements.txt`（`--upgrade` 追加）→ `btcctl init-db` → 可选回填。幂等，可反复执行 |
| `update` | `--no-backup`、`--start` | 校验 `.venv` → 运行中则停止 → 备份 `pre-update` → `git pull --ff-only`（非 git 仓库仅提示）→ 升级依赖 → 初始化数据库 → `--start` 时后台启动 |
| `uninstall` | `--purge-data`、`--yes` | 交互确认（或 `--yes`）→ 停止服务 → 强制备份 `pre-uninstall` → 删除 `.venv` → `--purge-data` 时删除 `data/`、`backups/`、`.env` |
| `start` | `--daemon` | 端口占用检查 → 前台运行 uvicorn；`--daemon` 时后台启动，写 `.runtime/server.pid`，日志追加到 `logs/platform.log`，最多等 25 秒做 `/healthz` 探测 |
| `stop` | 无 | 读 PID 文件：Windows `taskkill /PID /T /F`，Linux `SIGTERM`→最多 6 秒→`SIGKILL`；最后删除 PID 文件 |
| `restart` | 无 | 先 `stop_service()`，再以 **daemon 模式**启动（固定 `--daemon`，不可选前台） |
| `status` | 无 | 打印目录、`.venv` 是否存在、PID、端口监听、`/healthz`、数据库文件大小 |
| `doctor` | 无 | 检查 Python ≥3.11、`.venv`、`.env`、`data/btc.db`、端口与 `/healthz`，并在 `.venv` 存在时执行 `pip check`；有问题返回 1 |
| `backup` | `--label`（默认 `manual`） | 转调 `btcctl backup --label` |
| `restore` | `--file`（必填）、`--yes` | 转调 `btcctl restore --file [--yes]` |
| `menu` | 无 | 交互式菜单：status / start / stop / health / backfill / gap-repair / backup(`menu`) / restore / update --start / doctor |

```bash
# Windows
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/platformctl.py status
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/platformctl.py start --daemon
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/platformctl.py backup --label weekly
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/platformctl.py restore --file backups/btc-backup-20260926-205840-drill.tar.gz --yes

# Linux
.venv/bin/python scripts/platformctl.py doctor
.venv/bin/python scripts/platformctl.py update --start
```

退出码：`install` 完成返回 0；`update` 在缺少 `.venv` 时返回 2；`uninstall` 取消时返回 1；`start` 端口被占用返回 2；`doctor` 发现阻塞问题返回 1；`backup` 失败返回 2。

## btcctl —— 业务运维

| 子命令 | 参数 | 行为要点 |
| --- | --- | --- |
| `init-db` | 无 | `init_db()` + `enable_timescaledb()` + `seed_all()`，打印各表行数 |
| `backfill` | `--start`（默认取 `BACKFILL_START_DATE`）、`--interval`（默认 `1d`）、`--reset` | 断点续传；完成时报告新增根数与覆盖至日期，未完成报告 `stopped_at` 与原因；列出所有源都无数据的窗口 |
| `incremental` | `--interval` | 从本地最新一根往后补 |
| `tick` | 无 | 抓一次最新价并落库；失败返回 2 且明确「不会写入任何假数据」 |
| `gap-repair` | `--interval` | 扫描并补齐本地缺口 |
| `quality` | `--interval` | 打印完整度、根数、缺失数与覆盖区间；无数据返回 2 |
| `collect-all` | 无 | 依次跑衍生品 / 链上 / 情绪 / 宏观 / ETF 采集，逐项报告 |
| `stats` | 无 | 各数据表行数 |
| `coverage` | `--interval` | 本地历史覆盖区间与根数 |
| `health` | 无 | 数据源健康面板（总数/健康/未配置/已停用/今日失败/健康率 + 每源状态、延迟、评分、最近错误） |
| `probe` | 无 | 一键测试所有数据源连通性（`router.probe_all()`） |
| `replay` | `--date`（必填）、`--perspective`（`then`\|`aftermath`，默认 `then`） | 打印回放 JSON（截断到 4000 字符）；失败返回 2 |
| `backtest` | `--strategy`(dca_fixed)、`--name`、`--start`(2018-01-01)、`--end`、`--freq`(monthly\|weekly)、`--amount`(1000)、`--capital`(0)、`--oos` | 打印投入本金/最终资产/净收益/ROI/CAGR/最大回撤/回撤恢复天数/Sharpe/Sortino/波动率/平均成本/持有 BTC/手续费，以及 warnings 与样本外区间 |
| `backup` | `--label`（默认 `manual`） | 调用 `scripts/backup.py::create_backup()` |
| `restore` | `--file`（必填）、`--yes` | 调用 `restore_backup()`，`--yes` 跳过交互确认 |
| `serve` | `--host`(127.0.0.1)、`--port`(8787)、`--reload` | 直接前台启动 uvicorn（`app.main:app`），`os.chdir(backend)` 并设置 `PYTHONPATH` |

```bash
# Windows
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/btcctl.py health
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/btcctl.py backfill --start 2013-01-01 --interval 1d
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/btcctl.py replay --date 2021-11-10 --perspective then
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/btcctl.py backtest --strategy dca_valuation --start 2018-01-01 --oos

# Linux
.venv/bin/python scripts/btcctl.py probe
.venv/bin/python scripts/btcctl.py gap-repair --interval 1d
```

`btcctl` 的异步命令走 `asyncio.run()`，同步命令（`backup`/`restore`/`serve`）直接调用；`Ctrl+C` 会打印「断点已保存，重新执行同一命令可继续」并返回 130；未知命令打印「未知命令」返回 1。

## 演练脚本（真实环境验收用）

单元测试用 Fake Provider 不触网，因此「数据源真的挂了会怎样」必须靠这三个脚本验证。
它们都是**只读 / 沙箱**的：临时禁用的 Provider 一律在 `finally` 中复原，备份写进临时目录，绝不覆盖线上库与 `.env`。
JSON 报告输出到 `data/reports/`。

| 脚本 | 参数 | 作用 |
| --- | --- | --- |
| `scripts/provider_drill.py` | `--no-failover`、`--categories a,b` | 27 个 Provider 逐个真实探测 → 14 个类别主备取数 → 逐个禁用链首 Provider 验证自动切换 |
| `scripts/alert_failover_drill.py` | 无 | 需求四十二专项：基线 / 主源失效 / 全源失效三场景对照，验证「不伪造提醒也不崩溃」 |
| `scripts/backup_drill.py` | `--keep` | 备份 → 验签 → 解包打开恢复库核对表数 → 篡改拒绝两项负向测试 |
| `scripts/proxy_matrix_probe.py` | `地址字符串`、`--password`、`--timeout`、`--json` | 对同一代理做「SOCKS5 / HTTP CONNECT」×「多目标」矩阵探测，输出 SOCKS5 拒绝码（**REP=2 即代理侧规则不允许**）与放行域名清单 |
| `scripts/proxy_drill.py` | 无 | 直连 vs 走代理的对照演练，输出 `gained_via_proxy` / `still_unreachable` |

```bash
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/provider_drill.py
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/alert_failover_drill.py
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/backup_drill.py

# 只演练指定类别，跳过主源失效演练
.../python.exe scripts/provider_drill.py --categories market_price,ohlcv --no-failover
.../python.exe scripts/proxy_matrix_probe.py "user@1.2.3.4:1080" --timeout 15

```

退出码：`0` 表示通过（provider_drill 只要类别取数没有全灭即算通过，单个 Provider 受网络/限流影响不作硬断言），非 `0` 表示有未通过项，控制台会列出失败项名称。

## 已知局限 / 注意事项

- `restart` 固定以后台方式启动，无法用菜单/命令做「前台重启」。
- `platformctl status` 解析 `/system/health` 时使用 `(health.get("data") or health).get("summary")`，而该接口返回的是扁平结构（无 `data`/`summary`），因此「数据源 共 N 个…」这一行不会输出；查看数据源请用 `btcctl health` 或 `/system/providers/dashboard`。
- `platformctl` 的所有命令都依赖仓库根下的 `.venv`；用其它解释器（如本文示例路径）直接执行时，`start`/`update`/`install` 中凡调用 `venv_python()` 的步骤仍会去找 `.venv`，缺失即报「尚未安装（找不到 .venv）」。
- `platformctl` 没有 `restart --daemon` 之外的进程守护能力；生产长期运行请用 systemd（见「24 · 安装部署手册」）。
- Windows 下没有创建/删除计划任务的实现，`uninstall` 仅在删除时提示手动处理名为 `BTCPlatform` 的任务。
- `btcctl serve` 与 `platformctl start` 是两条并存的启动路径：前者支持 `--reload`（开发用，会关闭 access_log），后者支持 `--daemon` 与 PID 管理；不要同时用两者启动，否则端口冲突。
- `btcctl backfill --reset` 会先 `reset_checkpoint()` 再从起点重新抓取，耗时更长；写入本身靠 upsert 保证幂等。
