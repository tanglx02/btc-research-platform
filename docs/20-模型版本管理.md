# 20 模型版本管理

一句话定位：给每一个正在运行的模型登记一份可追溯档案（参数、开发区间、测试区间、有效条件、失效条件、检验状态），并要求做不到就写「未进行」，不允许含糊带过。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `backend/app/db/model_registry.py` | `CHANGELOG`、`MODELS` 档案列表、`_archive_text()`、`register_models()` |
| `backend/app/db/models.py` （451-463 行） | `ModelVersion` 表定义 |
| `backend/app/db/models.py` （466-473 行） | `ModelWeight` 表（因子权重与理由） |
| `backend/app/db/seed.py` （195-200 行） | 种子流程调用 `register_models()` 并计数 |
| `backend/app/api/research.py` （111-149 行） | `GET /research/models` 对外暴露档案 + `ModelWeight` |
| 各引擎 `MODEL_VERSION` | `cycle_v1 / valuation_v1 / risk_v1 / regime_v1 / forecast_v1 / ind_v1 / bt_v1`（`replay_v1` 另有定义但**未在档案中登记**） |

## 实现口径

### `ModelVersion` 表（`models.py`）

| 列 | 类型 / 说明 |
| --- | --- |
| `id` | Integer 主键 |
| `code` | String(64)，**唯一 + 索引**（幂等登记的依据） |
| `name` | String(128) |
| `kind` | String(32)，注释为 `cycle / valuation / risk / forecast / strategy` |
| `params` | JSON |
| `dev_period` | String(64)，开发区间 |
| `test_period` | String(64)，测试区间 |
| `metrics` | JSON，注释为「样本外表现」 |
| `active` | Boolean，默认 `False` |
| `notes` | Text（由 `_archive_text()` 生成） |
| `created_at` | DateTime，默认 `utcnow` |

`ModelWeight`：`model_code / factor / weight / rationale / updated_at`，在 API 中按 `model_code` 分组挂到每个模型下。

### `register_models()`

- 流程：对每个档案生成 `notes = _archive_text(model)`，按 `code` 查已有行；**存在则逐字段覆盖**（`name / kind / params / dev_period / test_period / metrics / active / notes`），不存在则新增；最后统一 `commit`，返回写入条数。
- 幂等且不删除：注释明确「**不删除**已有的历史版本记录——旧模型版本档案必须可追溯」。
- `metrics` 列实际写入的是档案的 `validation` 字典（含 `oos_validated / walk_forward / parameter_sensitivity / plan|note`）。

### `_archive_text(model)` 生成的 `notes`

固定三段：「【什么情况下有效】」（`applicable_when`）、「【什么情况下失效 / 不能怎么用】」（`fail_when`）、「【检验状态】」（`validation` 各项）。

### 对外接口

`GET /research/models` 返回 `count` 与 `models[]`（含 `code / name / kind / params / dev_period / test_period / metrics / active / notes / weights / created_at`）以及 `disclaimer`：「标注「未进行样本外检验」的模型不得作为决策依据，只能作为描述工具。」

## 与其它模块的关系

- 引擎通过各自 `MODEL_VERSION` 常量把版本号写进输出体（`cycle / valuation / risk / regime / forecast` 的 `model_version`，`IndicatorEngine.VERSION`，`BacktestEngine.VERSION`）。
- `BacktestRun` 每行记录 `model_version` 与 `data_version`，回测结果与模型档案可互查（文档 17）。
- `seed.py` 在数据库初始化时调用 `register_models()`，保证档案随版本升级被刷新。
- `ModelWeight` 目前**没有任何写入代码**（仅在 API 中被读取），因此 `weights` 列表在现有数据下为空。

## 已知局限 / 注意事项

1. **档案与代码存在三处不一致（风险项）**：
   - `valuation_v1.params.factors` 声明 `volatility_env: 0.15`、`mvrv: 0.30`，而 `valuation.py` 实际用「相对 200 日均线偏离 0.20」和 `mvrv: 0.25`，代码中**没有 volatility_env 因子**；
   - `risk_v1` 档案写「六维」，`risk.py` 权重表含 7 个维度（多出 `trend 0.20`）；
   - `bt_v1` 档案写 `walk_forward: True`，但 `backtest_service.py` 对 `walk_forward` 与 `oos` 走同一分支、只切分一次。
2. **`replay_v1` 未登记**：`replay_service.MODEL_VERSION = "replay_v1"` 会出现在回放响应里，但 `MODELS` 与 `CHANGELOG` 中都没有对应档案，`GET /research/models` 查不到它。
3. **所有模型都未做严格样本外检验**：除 `ind_v1`（确定性公式）外，`oos_validated` 均为 `False`，`test_period` 明确写「未进行严格样本外检验」。按接口 disclaimer，这些模型只能作为描述工具。
4. **`metrics` 列名不副实**：列注释写「样本外表现」，实际存的是 `validation`（检验状态与计划）字典；里面只有布尔标记与 `plan` 文字，没有任何数值指标。
5. **`ModelWeight` 表是空壳**：有表、有 API 读取逻辑，但没有任何写入代码，因子权重展示功能实际不可用。
6. **`register_models()` 按 `code` 覆盖而非新增版本行**：注释说「保留历史版本号」，但同 `code` 的档案被就地覆盖，历史上某一版参数**不可回溯**（只有 `CHANGELOG` 文字记录了变更）。真正的版本化需要引入版本号维度。
7. **`params` 是手写字典，与代码无自动同步**：参数改了而档案没改就会出现第 1 条那样的偏差；当前没有校验/测试来发现这种漂移。
8. `dev_period` 都是手写的「2013-01 ~ 2026-09」字符串，不与本地实际 K 线覆盖（`candle_coverage()`）对齐，也未随数据回填更新。
9. 当前**未提供**：模型启停开关（`active` 字段存在但没有任何逻辑读取它）、模型 A/B 对比、模型性能指标的自动回填、以及按版本回滚能力。
