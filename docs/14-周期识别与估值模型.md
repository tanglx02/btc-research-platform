# 14 周期识别与估值模型

一句话定位：用趋势/动量/估值/情绪/杠杆五个维度给「当前处在什么位置」打标签，并输出支持证据与反向证据，全部结论都是对**当前状态**的描述，不含买卖指令。

## 代码位置

| 文件 | 作用 |
| --- | --- |
| `backend/app/engines/cycle.py` | `CycleEngine`，十阶段周期判定 + 历史相似窗口 |
| `backend/app/engines/valuation.py` | `ValuationEngine`，五档估值状态与因子贡献 |
| `backend/app/engines/regime.py` | `MarketRegimeEngine`，把八类状态合成一句市场状态描述 |
| `backend/app/services/market_service.py` （308-339 行） | 唯一线上装配点：`valuation -> cycle -> risk -> regime` |
| `backend/app/services/replay_service.py` （101-103 行） | 回放场景下的调用（参数更少） |
| `backend/app/db/model_registry.py` | `cycle_v1 / valuation_v1 / regime_v1` 三份模型档案 |

## 实现口径

### ValuationEngine（`MODEL_VERSION = "valuation_v1"`）

`evaluate(indicators, onchain=None)` 的加权因子（缺失因子不参与，权重重新归一化）：

| 因子 | 权重 | 打分映射 |
| --- | --- | --- |
| `price_percentile` 价格历史分位 | 0.30 | 直接使用分位值（0-100） |
| `drawdown` 距历史高点回撤 | 0.25 | `_drawdown_to_score`：`-80% → 0 分`，`0% → 100 分`，线性截断 |
| 相对 200 日均线偏离 | 0.20 | `_deviation_to_score`：`-50% → 10`，`0% → 35`，`+100% → 75`，`+200% → 100`（分段线性） |
| `mvrv` | 0.25 | `_mvrv_to_score`：`≤1 → 10`，`1-2 → 10~35`，`2-3 → 35~65`，`3-4 → 65~90`，`>4 → 90+`（封顶 100） |

- 状态切分 `_score_to_state`：`<20 deep_undervalue` / `<40 undervalue` / `<60 fair` / `<80 overvalue` / 否则 `extreme_overvalue`。
- 置信度 `_confidence(weights_used, factors)`：`0.5 + 0.5 × 已用权重总和`；因子数 `< 2` 时再乘 0.7；区间 `[0.15, 0.95]`。
- 输出：`state / state_cn / description / score / confidence / contributions[] / missing_factors[] / model_version / disclaimer`。
- MVRV 缺失时向 `missing_factors` 追加「MVRV（需要付费链上数据源，当前未配置）」，权重归一化后继续计算——**不是填 0 分**。

### CycleEngine（`MODEL_VERSION = "cycle_v1"`）

`analyze(indicators, valuation_state, sentiment_index, funding_annualized, drawdown_from_ath, candles)`：

| 维度 | 打分规则 |
| --- | --- |
| 趋势 `trend` | 价格 > MA200：`+1.0`；否则 `-1.0`；MA50 > MA200：`+0.5`，否则 `-0.5` |
| 动量 `momentum` | `change_30d > 15`：`+1.0`；`< -15`：`-1.0`；RSI > 70：`+0.5`；RSI < 30：`-0.5` |
| 估值 `valuation` | 由估值状态映射：`extreme_overvalue +1.5` / `overvalue +0.7` / `undervalue -0.7` / `deep_undervalue -1.5` |
| 热度 `heat` | 恐慌贪婪指数 ≥ 75：`+1.0`，≤ 25：`-1.0`；资金费率年化 > 40%：`+1.0`，< -10%：`-0.5` |

- 总分 `total = trend + momentum + valuation + heat`，`_classify` 阈值：`≥4.0`（RSI>70 → `top_risk`，否则 `acceleration`）/ `≥2.0`（动量>0 → `markup`，否则 `distribution`）/ `≥0.5 recovery` / `> -1.0 range` / `> -2.5 correction` / 回撤 ≤ -60% `deep_bear` / ≤ -35% `accumulation` / 否则 `bear`。共 10 个阶段（常量 `PHASES`）。
- 置信度 `_confidence(n_points) = clamp(0.35 + 证据条数 × 0.07, 0.3, 0.9)`，证据条数 = 支持证据 + 反向证据。
- 输出包含 `evidence`（支持）与 `counter_evidence`（反向）两组，逐条带 `dim` 维度名与中文说明；固定附 `note`：「周期阶段是对当前状态的统计归类和描述，不是对未来走势的承诺。」
- `_find_similar_periods(candles, price, ma200, rsi, dd, top_n=3)`：要求 `len(candles) >= 260`，用 `|历史偏离差|×2 + |回撤差|/100` 作距离，取最近 3 个窗口，并给出该窗口之后 30/90 日的实际涨跌幅。

### MarketRegimeEngine（`MODEL_VERSION = "regime_v1"`）

| 子状态 | 判定 |
| --- | --- |
| `trend_state` | 价与 MA50 同在 MA200 上方：`strong_uptrend`（30 日涨幅 > 10%）/ `uptrend`；同在下方的对称分支；否则 `sideways`；数据缺失 `unavailable` |
| `capital_flow_state` | ETF 7 日净流 > 5e8 `strong_inflow`；> 0 `mild_inflow`；< -5e8 `strong_outflow`；否则 `mild_outflow`；无数据 `unavailable` |
| `derivative_state` | 资金费率年化 > 60 `overheated_long`；> 20 `crowded_long`；< -20 `crowded_short`；否则 `balanced`；无数据 `unavailable` |
| `macro_state` | 仅用 `dxy_change_30d`（阈值 ±2）与 `us10y_change_30d`（阈值 ±0.4）计分，≥1 `tightening`，≤-1 `easing`，否则 `neutral`；缺变化率时 `neutral`，缺宏观数据时 `unavailable` |
| `sentiment_state` | ≥80 `extreme_greed` / ≥60 `greed` / ≥45 `neutral` / ≥25 `fear` / 否则 `extreme_fear` |
| `onchain_state` | 只有 `neutral` 与 `unavailable` 两档（由 `onchain_available` 布尔决定） |

- 置信度：`available_modules / 8 × 0.8 + 0.15`，区间 `[0.2, 0.95]`；`unavailable_modules` 列出缺失模块名。
- 不输出 BUY/SELL，只输出 `regime` 短语与 `summary_cn`（末尾固定「这只是对当前环境的客观描述，不构成买卖建议。」）。

## 与其它模块的关系

- 上游是指标引擎的 `latest` 字段（见文档 13）；下游 `RiskEngine`（消费 `valuation_state`）与前端「市场状态」卡片。
- `market_service.analysis()` 同时装配估值/周期/风险/综合状态，`overview()` 再把它挂到首页。
- `replay_service` 复用同一套引擎，但只传 `valuation_state`，因此回放里的周期/风险维度比实盘少。
- 三份模型的参数、开发区间、失效条件登记在 `model_registry.py`，经 `GET /research/models` 暴露。

## 已知局限 / 注意事项

1. **付费数据源依赖**：MVRV 需要付费链上 Provider（`GLASSNODE_API_KEY` / `CRYPTOQUANT_API_KEY`，见 `backend/app/core/config.py`）。未配置时不提供任何 MVRV 数据，估值引擎只会在 `missing_factors` 里声明缺失并降权，**绝不用估算值顶替**；此时估值权重实际变为 分位 0.30 / 回撤 0.25 / 均线偏离 0.20 归一化。
2. **档案与代码不一致（风险项）**：`model_registry.py` 中 `valuation_v1.params.factors` 写的是 `price_percentile 0.30 / drawdown 0.25 / volatility_env 0.15 / mvrv 0.30`，但 `valuation.py` 实际用的是 `0.30 / 0.25 / 均线偏离 0.20 / mvrv 0.25`，**代码中不存在 volatility_env 因子**。以代码为准，档案需修正。
3. **档案与代码不一致（风险项）**：`risk_v1` 档案写「六维」，而 `risk.py` 的 `weights` 含 7 个维度（多了 `trend 0.20`）。见文档 15。
4. `_find_similar_periods` 在现有两个调用点（`market_service:309`、`replay_service:102`）**都没有传 `candles`**，因此线上 `similar_periods` 恒为空数组；该函数带未来收益字段（`return_30d_pct`/`return_90d_pct`），若将来接入需明确标注为事后视角。
5. 周期打分是**人工设定的经验权重**，未做参数优化，也不存在过拟合；但同样意味着它没有被优化到历史最优（档案中已写明）。三份模型的 `oos_validated / walk_forward / parameter_sensitivity` 全部为 `False`，`test_period` 均写「未进行严格样本外检验」——**按档案声明，不得作为决策依据，只能作为描述工具**。
6. 估值低不等于要涨：代码注释与 `disclaimer` 明确「估值只描述当前相对历史的位置，不构成买卖建议」。
7. 宏观维度只用变化率做方向判断，不使用绝对水平（`dxy`/`us10y` 仅出现在原因文案里），避免臆造数值。
8. 当前**未提供**：减半周期硬编码（`hardcoded_halving_cycle: False`）、链上多指标估值（`onchain_state` 只有 neutral/unavailable 两档）、周期阶段的历史准确率统计。
