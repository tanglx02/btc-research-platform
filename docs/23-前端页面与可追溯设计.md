## 页面结构与路由表

`app.js` 中的 `NAV` 既是侧栏分组也是路由来源，扁平化为 `ROUTES = { path: {title, fn, group} }`：`app.js:51-54`。

| 分组 | 路径（节选） | 渲染函数 |
| --- | --- | --- |
| 总览 | `/`、`/market`、`/timeline` | `overview`、`market`、`timeline` |
| 市场分析 | `/cycle`、`/valuation`、`/risk`、`/regime`、`/forecast` | 同名 |
| 链上与资金 | `/onchain`、`/flows`、`/etf`、`/derivatives`、`/options` | 同名 |
| 宏观与情绪 | `/macro`、`/sentiment` | 同名 |
| 回测与研究 | `/replay`、`/backtest`、`/strategies`、`/models`、`/indicators` | `replay`、`backtest`、`strategies`、`models`、`indicatorsPage` |
| 我的资金 | `/plans`、`/holdings`、`/dca` | 同名 |
| 系统 | `/settings`、`/providers`、`/quality`、`/jobs`、`/assistant`、`/admin` | 同名 |

hash 路由流程（`app.js:56-108`）：

1. `current()` 取 `location.hash`，去掉 `#` 后以 `?` 拆分出 `path` 与 `URLSearchParams`；
2. `route()` 查 `ROUTES`，未命中渲染「页面不存在」；命中则渲染侧栏高亮、设置 `document.title`、插入 loading 占位；
3. 从 `window.PM/PA/PR/PP/PS` 中取第一个匹配的同名函数作为渲染器，缺失时提示「该页面尚未实现」；
4. 用自增 `token` 比对 `currentRender`，丢弃迟到的旧请求渲染结果，防止慢请求覆盖新页面；
5. 渲染异常时输出 `C.unavailable(...)` + `C.rawBlock('页面渲染异常时的原始上下文', {path, params})`。

监听与刷新：`window.addEventListener('hashchange', route)`；`App.reload()` 重写 `location.hash` 后再次 `route()`；顶栏 `⟳` 按钮与 `visibilitychange` 都会触发刷新。

## 普通模式 / 专业模式

`core.js` 的 `C.State`：`mode` 存于 `localStorage['btc_mode']`，默认 `simple`；`setMode()` 同时切换 `body.mode-pro` 类与按钮高亮。专业模式用于展示原始数据与计算过程，具体差异由各页面内的 `C.State.isPro()` 判断与 CSS 控制。

## 可追溯的三层实现

### 第一层：数据来源声明 `C.sourceBlock(src)`（`core.js:162-192`）

任何返回值中的 `source` 对象都会被渲染为：来源名称、是否 `used_fallback`（已切换备用源）、质量徽章、置信度、响应耗时、数据时间（含「N 分钟前」）、切换原因，以及 **attempts 尝试链路表格**（数据源 / 成功或失败 / 延迟 / 失败原因）。这意味着「为什么用了这个源、为什么没用那个源」在页面上有直接答案。

### 第二层：原始 JSON `C.rawBlock(title, obj)`（`core.js:155-159`）

`<details><summary>…（原始数据）</summary><pre>JSON.stringify(obj, null, 2)</pre></details>`，内容经 `esc()` 转义。每页都在关键结论下方挂载接口原始返回，出现频次：

| 文件 | rawBlock 调用次数 |
| --- | --- |
| `pages-analysis.js` | 17 |
| `pages-research.js` | 10 |
| `pages-market.js` | 8 |
| `pages-system.js` | 5 |
| `pages-portfolio.js` | 3 |

此外 `app.js:105` 在页面渲染异常时也会输出原始上下文。

### 第三层：交叉验证 `C.crossValidationBlock(cv)`（`core.js:194-217`）

显示判定结论（`VERIFIED` / `CROSS_VERIFIED` / `CONFLICT` / `SINGLE_SOURCE`）、参与源数量、中位值、最大偏差与容差；当源数 > 1 时列出每个源的值与偏差。冲突时明确提示「系统不会偷偷选一个源」。

### 降级表达 `C.unavailable(reason, extra)`（`core.js:243-247`）

模块不可用时不填假数据，而是输出原因 + 可选原始返回 + 固定说明：「数据源失效时只关闭该模块，其余功能照常运行，且绝不使用模拟数据代替」。

## 已知局限 / 注意事项

- 管理令牌靠前端自己保存：`core.js` 的 `AdminAuth` 存在 `sessionStorage`（键 `btc_admin_token`），请求头 `X-Admin-Token` 只在**已填过**时才带上。填的地方有两处——`/admin` 页的「管理员令牌」输入框，以及 `/settings` 页顶部的令牌输入框。**没填时生产环境下的管理操作（`test-all`、`jobs/{id}/run`、`backfill`、保存配置、写操作）会被后端拒绝**；开发环境（`APP_ENV≠production`）后端免令牌。令牌只存当前标签页，刷新/换页后需重填。
- `/admin` 页提交 Provider 变更时用 `action` 字段，后端 `ProviderUpdateRequest` 不接受该字段，实际操作不生效（详见「22 · API 接口文档」）。
- `frontend/static/js/views/` 目录存在但为空，当前没有按 view 拆分的实现。
- 图表依赖本地 `static/vendor/echarts.min.js`，离线可用；但该 vendor 文件需要随代码一起部署，缺失时图表区域不渲染。
- 路由仅支持 hash 形式，未使用 History API；`index.html` 由 FastAPI 以 `FileResponse` 返回，Nginx 部署时需 `try_files $uri $uri/ /index.html`。
