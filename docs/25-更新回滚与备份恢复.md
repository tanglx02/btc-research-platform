# 25 · 更新回滚与备份恢复

更新、卸载、备份、恢复的真实命令与内部流程；回滚部分明确标注哪些能力代码实现里没有。

## 代码位置

| 文件 | 涉及命令 |
| --- | --- |
| `scripts/platformctl.py` | `update`、`uninstall`、`backup`、`restore`（`cmd_update` / `cmd_uninstall` / `cmd_backup` / `cmd_restore` / `do_backup`） |
| `scripts/backup.py` | `create_backup()`、`restore_backup()`、`list_backups()` |
| `scripts/btcctl.py` | `backup --label`、`restore --file [--yes]`（转调 `scripts/backup.py`） |
| `scripts/windows/update.bat` `backup.bat` `restore.bat` `uninstall.bat` | Windows 薄壳 |
| `scripts/linux/update.sh` `backup.sh` `restore.sh` `uninstall.sh` | Linux 薄壳 |

## 备份产物与内容

`create_backup()` 生成 `BACKUP_DIR/btc-backup-{YYYYmmdd-HHMMSS}[-{label}].tar.gz`（时间戳为 UTC），包内结构：

| 目录 | 内容 |
| --- | --- |
| `db/` | SQLite：主库文件 + `-wal` + `-shm`（三者必须一起复制，否则会丢掉未 checkpoint 的写入）；PostgreSQL：`postgres.sql`（`pg_dump --no-owner --no-acl`） |
| `config/` | 仓库根下所有 `.env*` 文件（排除 `.env.example`），**含密钥** |
| `logs/` | 最近 3 个 `*.log`（按 mtime 排序） |
| `manifest.json` | `name`、`created_at`、`database_type`、`files[]`（role/path/bytes/db 文件带 sha256）、`warnings[]` |

备份失败情形会被写入 `manifest.warnings` 而不是静默成功：未找到 SQLite 文件、未安装 `pg_dump`、`pg_dump` 超时或失败。`do_backup()` 在 `btcctl backup` 返回非 0 时会中止后续操作并提示「以免破坏数据」。

## 备份命令

```bash
# 默认 label=manual
python scripts/platformctl.py backup
python scripts/platformctl.py backup --label weekly

# 等价的业务命令（直接调用 scripts/backup.py）
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/btcctl.py backup --label pre-update
```

Windows：`scripts\windows\backup.bat --label weekly`；Linux：`./scripts/linux/backup.sh --label weekly`。

自动化触发点：`platformctl update` 会先以 `pre-update` 标签备份，`platformctl uninstall` 会以 `pre-uninstall` 标签强制备份；两者均可用 `--no-backup`（仅 update）跳过。菜单中备份固定使用 `menu` 标签。

## 恢复命令与流程

```bash
# 交互确认（默认），需输入 yes
python scripts/platformctl.py restore --file backups/btc-backup-20260926-205840-drill.tar.gz
# 自动化场景跳过确认
python scripts/platformctl.py restore --file backups/xxx.tar.gz --yes

# 等价业务命令
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe scripts/btcctl.py restore --file backups/xxx.tar.gz --yes
```

`restore_backup()` 的实际步骤：

1. 解包到临时目录，要求存在 `manifest.json`，否则报「备份包结构异常/缺少 manifest.json，无法安全恢复」并返回 1；
2. 打印备份包信息（创建时间、数据库类型、文件清单），并提示「恢复会覆盖当前的数据库与 .env 配置」；
3. 未加 `--yes` 时必须输入 `yes` 才继续，否则原样退出；
4. SQLite：把 `db/` 下所有文件复制到 `DATA_DIR`（默认 `data/`）；PostgreSQL：用 `psql <url> -f postgres.sql` 导入，未安装 `psql` 直接报错返回 1；
5. 配置：把 `config/` 下文件复制回仓库根，已存在的旧文件先另存为 `.env.bak-{时间戳}`；
6. 清理临时目录并提示重启服务。

## 更新流程

```bash
python scripts/platformctl.py update            # 备份 → 更新代码 → 升级依赖 → 迁移 → 提示手动启动
python scripts/platformctl.py update --start    # 更新完成后自动后台启动
python scripts/platformctl.py update --no-backup
```

`cmd_update()` 的顺序：校验 `.venv` 存在（否则提示先 install）→ 若服务在运行则 `stop_service()` → 备份（`pre-update`）→ `_update_code()`→ `ensure_env_file()` → `install_deps(upgrade=True)` → `init_database()` → 可选启动。

`_update_code()` 的行为：仓库根存在 `.git` 时执行 `git pull --ff-only`（失败不中断，仅打印结果）；**非 git 仓库时只打印提示**「请手动把新版本代码覆盖到本目录后再继续」，然后继续后续步骤。

## 回滚

代码里**没有** `rollback` 子命令（未找到实现）。可行的回滚路径只有两条：

| 场景 | 操作 |
| --- | --- |
| 仅代码回退（git 部署） | `git log --oneline` 找到目标提交后 `git checkout <commit>` / `git reset --hard <commit>`，再 `python scripts/platformctl.py restart` |
| 数据 + 配置回退 | `python scripts/platformctl.py restore --file backups/更新前生成的 pre-update 包` |

建议顺序：先停服务（`platformctl stop`）→ 回退代码 → 恢复备份 → `platformctl start --daemon` → `platformctl status` + `btcctl coverage` 核对覆盖区间。

## 卸载

```bash
python scripts/platformctl.py uninstall                 # 交互式确认（输入 yes）
python scripts/platformctl.py uninstall --yes           # 跳过确认
python scripts/platformctl.py uninstall --purge-data    # 连同 data/、backups/、.env 一起删除（不可逆）
```

流程：打印风险说明 → 确认 → `stop_service()` → 强制备份（`pre-uninstall`）→ 删除 `.venv` → 仅当 `--purge-data` 时删除 `data/`、`backups/`、`.env`；Windows 平台额外提示手动删除名为 `BTCPlatform` 的计划任务（若注册过）。

## 已知局限 / 注意事项

- 没有内建回滚命令，也没有版本号/标签记录：更新前务必确认 `pre-update` 备份已生成（`ls backups/`）。
- `scripts/backup.py` 中的 `list_backups()` 函数没有对应的 CLI 子命令（未找到实现），查看历史备份只能用 `ls backups/` 或 `tar -tzf`。
- 恢复只覆盖数据库与 `.env*`，**不回滚代码**；代码回退必须自行用 git 或人工覆盖。
- PostgreSQL 备份依赖外部 `pg_dump`，恢复依赖 `psql`；二者缺失时备份会带 warning 跳过、恢复会直接失败。
- 备份包包含明文密钥（`.env`），必须限制 `backups/` 目录权限，且不应随代码一起分发。
- 恢复完成后需要重启服务才能生效；脚本提示的重启命令是 `python scripts/btcctl.py serve`（前台），后台部署请用 `platformctl start --daemon` 或 `systemctl restart`。
- `update` 使用 `pip install --upgrade`，会把依赖升到满足下限的最新版本，可能与已验证版本不一致；如需稳定复现应先固定 `requirements.txt`。
